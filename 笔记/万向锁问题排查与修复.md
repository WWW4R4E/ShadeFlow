# 万向锁问题排查与修复全记录

## 问题背景

在 ShadeFlow 引擎中，相机围绕目标点进行轨道旋转时，出现万向锁（Gimbal Lock）现象：当俯仰角接近 ±90° 时，旋转控制崩溃，相机在两个状态之间振荡，无法正常操作。

## 初始状态分析

### Transform 结构体（对象旋转）

```zig
const Transform = struct {
    position: [3]f32,
    rotation: [3]f32,  // 欧拉角
    scale: [3]f32,

    pub fn getWorldMatrix(self: *const Transform) [4][4]f32 {
        const rot_x = Matrix.createRotationXMatrix(self.rotation[0]);
        const rot_y = Matrix.createRotationYMatrix(self.rotation[1]);
        const rot_z = Matrix.createRotationZMatrix(self.rotation[2]);
        // Scale * Rx * Ry * Rz * Translate
    }
};
```

**问题**：使用欧拉角存储旋转，`getWorldMatrix` 分别创建 X/Y/Z 三个旋转矩阵再相乘。这是经典的欧拉角万向锁根源——当 Y 轴旋转（pitch）接近 ±90° 时，X 和 Z 轴重合，失去一个自由度。

### Camera 结构体（相机旋转）

相机已经使用了四元数，但实现方式存在问题。

---

## 第一次尝试：Transform 改用四元数

### 做法

1. 将 `Quaternion` 从 Camera.zig 提取到共享的 `src/utils/math/Quaternion.zig`
2. 给 Quaternion 添加 `toMatrix()` 方法
3. 将 `Transform.rotation` 从 `[3]f32` 改为 `Quaternion`
4. `getWorldMatrix` 改为 `self.rotation.toMatrix()` 一次计算旋转矩阵

### 结果

Transform 的万向锁解决了，但相机的万向锁依然存在。

---

## 第二次尝试：Camera 用 yaw/pitch 角度 + 球坐标

### 做法

将 Camera 的旋转从四元数改为存储 yaw/pitch 角度，用球坐标计算位置：

```zig
yaw: f32 = 0.0,
pitch: f32 = 0.0,

fn computePosition(self: *const Camera) [3]f32 {
    return .{
        target.x + distance * cos(pitch) * sin(yaw),
        target.y + distance * sin(pitch),
        target.z + distance * cos(pitch) * cos(yaw),
    };
}
```

### 现象

没有万向锁了，但 pitch 被限制在 ±89°，无法旋转到任意角度。

### 失败原因

yaw/pitch 角度本质上还是欧拉角，只是把问题从"万向锁"变成了"角度限制"。

---

## 第三次尝试：四元数累积旋转（世界轴）

### 做法

用四元数做增量旋转，yaw 绕世界 Y 轴，pitch 绕相机局部 X 轴：

```zig
const yaw_quat = Quaternion.fromAxisAngle(.{ 0.0, 1.0, 0.0 }, delta_x * speed);
const local_right = self.rotation.rotateVector(.{ 1.0, 0.0, 0.0 });
const pitch_quat = Quaternion.fromAxisAngle(local_right, delta_y * speed);
self.rotation = pitch_quat * yaw_quat * self.rotation;
```

### 现象

可以自由旋转了，但转到背面后控制反转——鼠标向左，物体却向右移动。

### 失败原因

pitch 旋转在**世界空间**计算。当相机翻转后，局部 X 轴相对屏幕空间反转了，导致控制方向反转。

---

## 第四次尝试：屏幕空间动态计算旋转轴

### 做法

每帧从当前视线方向动态计算旋转轴，使其始终对应屏幕的水平/垂直方向：

```zig
const view = normalize(target - position);
const right = normalize(cross(view, world_up));  // 屏幕水平轴
const up = cross(right, view);                     // 屏幕垂直轴
```

### 现象

回到最初的振荡问题——当视线接近世界 Y 轴时，`cross(view, world_up)` 退化为零向量，旋转轴每帧剧烈跳动。

### 失败原因

`view × world_up` 叉积在视线平行于 Up 时退化，这是所有使用固定世界 Up 参考的轨道相机的固有数学限制。

---

## 第五次尝试：正确的四元数累积（局部空间 pitch）

### 做法

核心公式改为 `R' = dYaw_world × R × dPitch_local`：

```zig
const dYaw = Quaternion.fromAxisAngle(.{ 0.0, 1.0, 0.0 }, delta_x * speed);
const dPitch = Quaternion.fromAxisAngle(.{ 1.0, 0.0, 0.0 }, delta_y * speed);
self.rotation = dYaw * (R * dPitch);  // pitch 在局部空间应用
```

**关键区别**：`dPitch` 放在 `R` 的**右边**，表示在局部空间旋转。数学上等价于先将 pitch 转换到世界空间 `R × dPitch × R⁻¹`，再应用到 R 上。

### 现象

旋转平滑，可以过 90°，但过 90° 后控制没有按预期反转——仍然和正面时一样。

### 失败原因

View matrix 仍然使用固定 `up = (0,1,0)` 计算 `right = cross(forward, up)`。当相机倒过来时，forward 和 up 平行，叉积退化，视图矩阵出错，导致屏幕显示的旋转方向与预期不符。

---

## 最终解决方案

### 核心思路

1. **旋转公式**：`R' = dYaw × R × dPitch`（pitch 在局部空间）
2. **View matrix**：直接从四元数推导相机局部轴，完全不依赖固定 up 向量

### 代码实现

**Camera 结构体**：

```zig
pub const Camera = struct {
    target: [3]f32 = .{ 0.0, 0.0, 0.0 },
    rotation: Quaternion = Quaternion{},
    distance: f32 = 3.0,
    position: [3]f32 = .{ 0.0, 0.0, 3.0 },
    // ...
};
```

**位置计算**（注意正号）：

```zig
fn computePosition(self: *const Camera) [3]f32 {
    const offset = self.rotation.rotateVector(.{ 0.0, 0.0, self.distance });
    return .{ target[0] + offset[0], target[1] + offset[1], target[2] + offset[2] };
}
```

**View matrix**（从四元数直接推导三轴）：

```zig
pub fn getViewMatrix(self: *Camera) [4][4]f32 {
    self.position = self.computePosition();

    const cam_right   = self.rotation.rotateVector(.{ 1.0, 0.0, 0.0 });
    const cam_up      = self.rotation.rotateVector(.{ 0.0, 1.0, 0.0 });
    const cam_forward = self.rotation.rotateVector(.{ 0.0, 0.0, -1.0 });

    return [4][4]f32{
        { cam_right[0], cam_up[0], -cam_forward[0], 0.0 },
        { cam_right[1], cam_up[1], -cam_forward[1], 0.0 },
        { cam_right[2], cam_up[2], -cam_forward[2], 0.0 },
        { -dot(cam_right, pos), -dot(cam_up, pos), dot(cam_forward, pos), 1.0 },
    };
}
```

**旋转控制**：

```zig
pub fn rotateAroundCenter(self: *Camera, delta_x: f32, delta_y: f32) void {
    const dYaw = Quaternion.fromAxisAngle(.{ 0.0, 1.0, 0.0 }, delta_x * 0.01);
    const dPitch = Quaternion.fromAxisAngle(.{ 1.0, 0.0, 0.0 }, delta_y * 0.01);
    self.rotation = dYaw * (self.rotation * dPitch);  // 局部空间 pitch
    self.position = self.computePosition();
}
```

### 为什么这次成功了

| 之前失败的方式 | 问题 |
|---|---|
| 欧拉角 | 万向锁（轴重合） |
| yaw/pitch 角度 + 球坐标 | 需要限制 pitch 范围 |
| 四元数 + 世界空间 pitch | 翻转后控制反转 |
| 四元数 + 屏幕空间轴 | 叉积退化导致振荡 |
| 四元数 + 局部空间 pitch + 固定 up 的 view matrix | view matrix 在翻转时退化 |

**最终方案的两个关键**：

1. **旋转公式 `R' = dYaw × R × dPitch`**：pitch 在局部空间应用，数学上保证了无论相机如何翻转，pitch 始终绕相机的"右耳"方向旋转，控制方向始终一致。

2. **View matrix 从四元数推导**：`cam_right = R × (1,0,0)`, `cam_up = R × (0,1,0)`, `cam_forward = R × (0,0,-1)`。这三个轴始终正交、始终有效，完全避免了 `cross(forward, fixed_up)` 的退化问题。

### 行为说明

- **0°~90°**：鼠标往上 → 往上看
- **过 90°**：局部 X 轴相对世界空间翻转，鼠标往上变成往下看（自然反转）
- **180°**：完全倒过来，上下左右全反
- **360°**：回到原始状态

这与 Blender 的轨道相机行为一致——控制方向随视角平滑反转，无跳跃、无振荡、无角度限制。
