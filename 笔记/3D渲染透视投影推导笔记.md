# 3D渲染透视投影推导笔记

## 一、基础铺垫：窗口、视口与投影矩阵的作用
最开始的困惑：「调节窗口大小，物体会跟着缩放吗？」要回答这个问题，先理清三个核心概念的关系：
### 1. 三个核心概念
- **窗口**：操作系统层面的可显示区域，比如800x600像素的窗口，是最终的显示画布。
- **视口（Viewport）**：引擎告诉GPU「把渲染结果画到窗口的哪块区域」，通常默认和窗口客户区等大。窗口缩放时，视口一般同步等比例变化。
- **投影矩阵（Projection Matrix）**：3D渲染的核心组件，作用是把三维世界的视锥体（相机能看到的区域）「压扁」成标准化设备坐标（NDC）的立方体，直接决定了3D内容如何映射到2D屏幕。

### 2. 窗口缩放对物体的影响结论
- 物体本身的**世界坐标大小永远不变**：你代码里的`size=1.0`、位置`0.1,0.1,0.1`是定义在世界坐标系中的，和窗口无关。
- 窗口变化是否改变物体的屏幕显示效果，完全看投影矩阵的配置：
  - 仅改窗口像素分辨率（比如800x600→1600x1200，宽高比不变）：视口变大，投影矩阵不变，物体像素变多更清晰，但**表观大小不变**。
  - 改窗口宽高比（比如4:3→16:9）：若引擎同步更新投影矩阵的宽高比参数，只会改变水平视野范围，近处物体的垂直显示大小仍不变。
  - 只有引擎错误地把窗口像素直接绑定到投影（比如正交投影直接用像素值算范围），才会导致窗口缩放物体跟着变。

## 二、世界单位：代码中的1.0、0.1到底是什么？
承接上一部分「物体本身世界坐标不变」的结论，解答第二个困惑：「这些参数的单位是多少？对应屏幕多大？」
### 核心结论
- 这些是**无固有单位的世界单位**：1个单位可以是1米、1厘米，完全由你的场景约定决定，本身和屏幕像素没有绑定关系。
- 一个世界单位最终显示多少像素，取决于完整渲染链路：
  ```
  世界坐标 → 观察坐标（相机空间，由相机位置/朝向决定） → 裁剪坐标（乘投影矩阵） → NDC（标准化设备坐标，规则立方体） → 屏幕像素（视口变换，映射到窗口像素）
  ```

## 三、投影矩阵核心：缩放因子的推导
投影矩阵的核心作用是把「相机视锥体」压成「NDC立方体」，其中**缩放因子（x_scale/y_scale）**是最核心的参数，行业通用做法是**先通过垂直视场角（FOV）计算垂直方向的缩放因子**，再推导水平方向。

### 3.1 先建立空间想象：垂直视场角（FOV）是什么？
用生活场景类比：
把相机想象成你手里的手电筒，发出的光是圆锥形光束：
- **垂直视场角（FOV）**就是这个光束在**垂直方向的张角**：
  - FOV小（比如30°）：像望远镜，光束集中，只能照亮很小区域，物体被放大。
  - FOV大（比如90°）：像广角镜，光束发散，能照亮很大区域，物体变小。
- 为什么用「垂直」FOV？因为屏幕高度是更稳定的参考，用垂直角度结合宽高比，自然能算出水平方向的视野范围。

### 3.2 核心几何关系：视窗高度公式
你推导的公式完全正确：
> 视窗高度 = 2 * 距离d * tan(α)，其中α = fov/2（FOV的一半）

物理意义：在**距离相机d**的位置，垂直方向能看到的总世界高度。比如FOV=90°，α=45°，tan(45°)=1，如果物体在距离d=10的位置，视窗高度就是`2*10*1=20`个单位，一个高度2的物体在这里仅占1/10的视野。

### 3.3 简化计算：选参考距离d=1
为了推导方便，我们选**d=1**（距离相机1个单位）作为参考平面：
- 此时视窗半高 = 1 * tan(α) = tan(fov/2)，记为`h`
- 视窗全高 = 2h = 2*tan(fov/2)
（之前提到的`h=tan(fov/2)`就是这里的半高，和你推导的全高公式完全对应，只是中间变量选了半高/全高的区别）

### 3.4 推导y_scale：从视窗到NDC的映射
NDC的垂直范围是**-1到1**，总高度正好是2。我们需要把参考平面（d=1）上的视窗全高`2h`，压缩到NDC的高度2：
```
缩放系数 = 目标高度 / 原始高度 = 2 / (2h) = 1/h = 1/tan(fov/2)
```
这就是代码里的`y_scale`！你提到的「约掉2」正好是这一步的化简，完全匹配你的推导逻辑。

### 3.5 水平缩放因子x_scale：结合宽高比
垂直方向的缩放系数`y_scale`是基于垂直FOV算的，水平方向需要根据窗口宽高比调整，避免画面拉伸：
```
x_scale = y_scale / aspect_ratio  // aspect_ratio = 窗口宽/窗口高
```
如果宽高比>1（窗口更宽），x_scale会小于y_scale，保证水平方向的内容不会被拉宽。

### 3.6 深度映射：z_scale与z_offset（OpenGL风格）
投影矩阵还要处理深度映射（把相机空间的Z值映射到NDC的Z范围），以你代码里的OpenGL风格（右手坐标系，NDC Z范围[-1,1]）为例：
- 相机看向-Z，Z值为负，近平面`near`、远平面`far`都是正数
- 推导得到：
  ```zig
  z_scale = -(far + near) / (far - near)
  z_offset = (-2 * far * near) / (far - near)
  ```
- 矩阵中第三行第四列的`-1.0`和第四行第三列的`z_offset`配合，实现透视除法（最终所有分量除以`-z`，实现近大远小）。

## 四、完整投影矩阵代码解析
对应你最开始的Zig代码，每一行都和上面的推导对应：
```zig
pub fn getProjectionMatrix(self: *const Camera) [4][4]f32 {
    const fov_rad = self.fov * std.math.pi / 180.0; // 把角度转弧度
    // 垂直缩放因子，对应3.4推导的y_scale
    const y_scale = 1.0 / @tan(fov_rad / 2.0); 
    // 水平缩放因子，对应3.5的x_scale
    const x_scale = y_scale / self.aspect_ratio;
    // 深度映射参数，对应3.6的推导
    const z_scale = -(self.far_plane + self.near_plane) / (self.far_plane - self.near_plane);
    const z_offset = (-2.0 * self.far_plane * self.near_plane) / (self.far_plane - self.near_plane);

    // 矩阵布局：列主序，对应渲染管线的乘法规则
    return [4][4]f32{
        [4]f32{ x_scale, 0.0, 0.0, 0.0 },       // 第一列：X轴缩放
        [4]f32{ 0.0, y_scale, 0.0, 0.0 },       // 第二列：Y轴缩放
        [4]f32{ 0.0, 0.0, z_scale, -1.0 },      // 第三列：深度映射 + 透视除法触发
        [4]f32{ 0.0, 0.0, z_offset, 0.0 },      // 第四列：深度常数项
    };
}
```

## 五、补充：DirectX风格的差异
OpenGL和DirectX的核心区别仅在于NDC的Z范围：
| 特性                | OpenGL风格（你的代码） | DirectX风格               |
|---------------------|------------------------|---------------------------|
| 坐标系              | 右手（相机看向-Z）     | 通常左手（相机看向+Z）     |
| NDC Z范围           | [-1, 1]                | [0, 1]（0近1远）          |

DX风格的投影矩阵只需修改深度映射部分（仍保持右手视图空间到DX NDC）：
```zig
pub fn getProjectionMatrixDXStyle(self: *const Camera) [4][4]f32 {
    const fov_rad = self.fov * std.math.pi / 180.0;
    const y_scale = 1.0 / @tan(fov_rad / 2.0);
    const x_scale = y_scale / self.aspect_ratio;
    // DX的Z映射到[0,1]，边界条件：z=-near→0，z=-far→1
    const depth_a = self.far_plane / (self.near_plane - self.far_plane);
    const depth_b = (self.far_plane * self.near_plane) / (self.near_plane - self.far_plane);
    return [4][4]f32{
        [4]f32{ x_scale, 0.0, 0.0, 0.0 },
        [4]f32{ 0.0, y_scale, 0.0, 0.0 },
        [4]f32{ 0.0, 0.0, depth_a, -1.0 },
        [4]f32{ 0.0, 0.0, depth_b, 0.0 },
    };
}
```

## 六、推导闭环：你的核心结论验证
你最后总结的直觉完全正确：
> 「简单来说我需要看到一个同样大小的内容区域，垂直视场小，那就需要更远的距离，反之亦然。所以它直接定义了距离和看到内容的多少关系？」

这正是FOV的物理意义：FOV和相机距离共同决定视野范围——FOV越小，要看到同样大小的内容，相机需要退得越远；FOV越大，则需要靠得越近。整个推导过程从直觉到公式完全自洽。
